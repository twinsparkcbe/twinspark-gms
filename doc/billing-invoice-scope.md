# Billing & Invoice Management — Feature & Use-Case List

**Status:** Confirmed and implemented (module workflow steps 1–3 complete).
**Relationship to source docs:** Implements spec §4.10 (Billing & Invoice
Management) and §7 (Invoice Numbering & Format Notes), scoped down to what's
buildable today. Fills in `services/shared/invoice.ts` and
`services/shared/gst-discount.ts`, previously left as stubs pending this
confirmation.

**Scope for this pass:** Sales Invoice only. Service Invoice (labour
charges, inventory-used section) is the same shared engine but can't be
built yet — the Service module doesn't exist. The shared helpers below are
written so Service plugs into them later without Sales being touched again.

---

## 1. What's already built (reused, not rebuilt)

- `getSale(supabase, id)` (`services/sales/sales.ts`) already returns a
  fully-joined `SaleRow` — customer, every line item, subtotal,
  installation total, GST, discount, grand total, invoice number. No new
  query or schema needed; this module is presentation-only on top of it.
- Sequential invoice numbering (`TW-S-000123`) is already generated by
  `record_sale()` and stored on the sale.
- The Sales list already has a stubbed "View invoice" button per row
  (`sales-table.tsx` — `Receipt` icon, no `onClick` yet) — this is the
  wiring point for reprints.

## 2. New: Business identity constants

- A single config file (e.g. `lib/business-info.ts`) holding the invoice
  header block: business name, address, phone, GSTIN. Not a database
  table — no Settings module is in scope, so this is a source-controlled
  constant the developer edits directly.
- **Standard suggested fields** (confirm/replace with real values before
  going live):
  - Business name: `Twinspark Tyres And Bike Garage`
  - Address: `Coimbatore, Tamil Nadu` (placeholder — needs exact street
    address)
  - Phone: placeholder — needs real number
  - GSTIN: placeholder — needs real number, line only renders if provided
    (blank/omitted GSTIN simply hides that row, doesn't break layout)

## 3. Invoice page (new route)

- `/sales/[id]/invoice` — dedicated print-optimized page, server-rendered
  from the sale id via `getSale()`. Not a modal — needs to be a real page
  so `window.print()` / the browser's Print dialog can target it directly,
  and so it has its own shareable URL for reprints.
- **Layout (A4), top to bottom:**
  1. Header: business name/address/phone/GSTIN (§2) + "TAX INVOICE" /
     "INVOICE" label, right-aligned Invoice No. and Invoice Date.
  2. Bill-to block: customer name, mobile, address (if given).
  3. Line items table: SL No, Description, Qty, Unit Price, Amount — same
     shape as the New Sale line-item table, so what staff built is exactly
     what prints.
  4. Installation Charges: itemized separately underneath products, never
     blended into the product subtotal (non-negotiable, carried over from
     scope doc §4/§7).
  5. Totals block: Subtotal → Installation Charges → GST (rate % + amount,
     if applicable) → Discount (if applicable) → **Grand Total** (bold,
     visually distinct).
  6. Footer: thank-you line + standard note ("Goods once sold are not
     taken back except as per Sale Return policy" or similar — placeholder
     wording, confirm exact text).
- **Print behavior:** on-screen, the page shows normal app chrome (nav,
  "Print Invoice" / "Back to Sales" buttons) plus the invoice content. A
  print stylesheet (`@media print`) hides everything except the invoice
  content when the browser Print dialog opens — no PDF library involved;
  "Save as PDF" is just the browser's own print destination.
- Access: both **Administrator** and **Sales Person** can view/print —
  matches Sales' existing access rule (both roles can create sales, so
  both can produce the resulting invoice).

## 4. Entry points

- **Immediately after recording a sale:** on success, New Sale redirects
  to `/sales/[id]/invoice` instead of the Sales list, so staff can print
  right away for the customer waiting at the counter.
- **Reprint any past sale:** the existing stubbed "Invoice" button in the
  Sales table (`sales-table.tsx`) links to the same route.

## 5. Non-goals for this pass

- No server-side PDF rendering (Puppeteer/headless Chrome) — browser print
  covers "printable + exportable as PDF" per spec §7 without new infra.
- No email/WhatsApp delivery of the invoice (out of scope per project
  instructions).
- No Service Invoice layout yet (Service module doesn't exist).
- No Settings UI for editing business info — constants file only.
